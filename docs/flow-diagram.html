NovaCRM Onboarding Agent — Implementation Flow

Multi-agent system that automates customer onboarding from deal close to Slack channel setup

1

Gmail Inbox Monitoring Integration

The orchestrator polls Gmail every 30 seconds, looking for unread emails matching deal notification patterns (subject contains "new deal", "closed won", etc.).

  • Uses Gmail API with OAuth2 authentication
  • Filters: is:unread subject:(new deal OR closed won)
  • Extracts subject, sender, body, and message ID

What happens next?

Email foundRaw email data passed to Intake Agent for parsing
No emailsLog "no new deals", sleep 30s, poll again
2

LLM Email Parsing Intake Agent

Claude extracts structured fields from the raw email body. The LLM is prompted to return a JSON object with exactly the fields we need.

  • Extracted fields: customer_name, customer_contact_email, ae_name, ae_phone, salesforce_opportunity_link
  • LLM response is parsed as JSON; if unparseable, the email is rejected
  • Plan tier is intentionally NOT extracted — that comes from the voice call
3

Field Validation Guardrail

Every parsed field is validated before the pipeline proceeds. The agent never guesses missing data.

  • All 5 required fields must be present and non-empty
  • Email format check (regex)
  • Phone number must have at least 10 digits
  • Salesforce link checked (warning, not blocking)

Validation outcome

All fields validProceed to voice call step
Missing / invalid fieldsLog validation errors with specifics, stop processing this email. Escalate for clarification.
4

Voice Call to AE Bland.ai

A real outbound phone call is placed to the AE using Bland.ai's Voice API. The AI voice agent asks the AE to confirm whether the customer is on Enterprise or Growth.

  • Personalized opening: "Hi {ae_name}, calling about {customer_name}…"
  • Asks for plan tier, then repeats back for confirmation
  • Call is recorded and transcribed
  • Agent polls Bland.ai for call completion (up to 3 minutes)
5

Voice Call Validation Guardrail

The transcript is analyzed for plan tier keywords and confirmation phrases. A confidence score is computed — the agent will NOT proceed unless it's ≥ 80%.

  • Enterprise signals: "enterprise", "30-day", "dedicated CSM"
  • Growth signals: "growth", "14-day", "pooled CSM"
  • Confirmation boost: "yes", "correct", "confirmed" adds +20% confidence
  • Ambiguity: If both tiers mentioned, confidence drops to 30%

Three possible outcomes

Clear confirmation (≥80%)Proceed with confirmed plan tier
Failed / ambiguousRetry up to 2 more times. After all retries fail → escalate to CS Manager for manual handling. Never guess the tier.
6

Duplicate Project Check Guardrail

Before creating anything, query Rocketlane for existing active projects matching this customer name.

Duplicate check result

No active duplicatesSafe to create new project
Active project existsBlock creation, log the conflict, flag for human review
7

Create Rocketlane Project Rocketlane API

The project is created via the Rocketlane API with the correct template and configuration based on the confirmed plan tier.

  • Enterprise: "Enterprise Onboarding - 30 Day" template, dedicated CSM, 30 days
  • Growth: "Growth Onboarding - 14 Day" template, pooled CSM, 14 days
  • Both include 4 phases: Kickoff → Data Migration → Configuration → Go-Live
  • If Rocketlane API is down, the error propagates and is logged
8

Create Slack Channel Communication Agent

A dedicated Slack channel is created for onboarding communication, personalized by plan tier.

  • Channel name: onb-{customer}-{tier}
  • Topic: Includes customer name, plan, duration, CSM type
  • Enterprise welcome: Mentions dedicated CSM, 30-day timeline, kickoff within 24h
  • Growth welcome: Mentions pooled support team, 14-day timeline
  • Slack failure doesn't block the project — it's logged and flagged for manual setup
9

Complete & Audit Done

The email is marked as read in Gmail, the full audit trail is logged, and the orchestrator resumes polling for the next deal.

  • Every step logged: timestamp, agent, action, inputs, outputs, rationale
  • Audit trail exportable as JSON for review
  • Email marked as read to prevent reprocessing

G1

Input Validation — Never Guess

Every required field (customer name, email, AE name, AE phone, Salesforce link) is validated with Pydantic + custom checks. If any field is missing, malformed, or empty, the agent stops and logs exactly what's wrong — it never fills in a guess.

G2

Voice Confirmation Gate — No Ambiguity Allowed

Project creation is blocked until the voice call returns a plan tier with ≥ 80% confidence. Low confidence, no answer, or ambiguous responses trigger retries (up to 2), then human escalation. The agent never assumes a tier.

G3

Retry + Escalation — Graceful Degradation

Failed voice calls retry up to 2 more times. After all retries exhaust, the system escalates to the CS Manager rather than blocking indefinitely or making a decision without data.

G4

Duplicate Detection — No Double Onboarding

Before creating a project, the agent queries Rocketlane for existing active projects with the same customer name (case-insensitive). Completed projects are ignored; active/in-progress ones block creation.

G5

Full Audit Trail — Every Decision Traced

Every agent action is logged with: timestamp, agent name, action type, full inputs and outputs, decision rationale, and success/failure status. Exportable as JSON for compliance and debugging.

G6

LLM Output Validation — Reject Garbage

If the LLM returns something that isn't parseable JSON, or returns text without the expected structure, the email is rejected and logged. No downstream processing happens on unstructured LLM output.
